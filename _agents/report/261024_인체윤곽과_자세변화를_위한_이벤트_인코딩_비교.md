# 인체 윤곽과 자세 변화를 위한 이벤트 인코딩 비교

작성일: 2026년 10월 24일

사람의 현재 윤곽과 빠른 자세 변화를 함께 잡으려면 **짧은 시간의 윤곽 표현과 시간 순서를 보존하는 모션 표현을 함께 사용**하는 것이 적절하다. 이번 두 세션의 시각 비교에서는 33ms 누적이 움직이는 팔의 현재 위치를 비교적 선명하게 남겼고, 100ms를 시간 구간으로 나누면 팔의 이동 순서를 볼 수 있었다. 200ms를 한 장으로 합치면 윤곽이 조밀해지는 대신 과거 팔 위치가 넓게 남았다.

시각화 기본값으로는 **33ms 극성 분리 누적과 약한 고립 점 제거**를 추천한다. 빠른 동작의 최근 위치를 강조하려면 **감쇠 시간 20ms의 시간 표면**을 함께 본다. 자세 추정 학습에는 **시간 구간별 양·음 극성을 분리한 입력**을 우선 제안한다. 아래 판단은 실제 생성한 영상과 추출 프레임에 근거한 정성 비교이며, 자세 추정 정확도의 순위를 의미하지 않는다.

## 데이터와 공통 조건

다음 두 세션의 `device0`에서 RGB 기준 앞 60초를 사용했다.

- 얼굴과 상체: `20260720_125338_040324_200_f`
- 전신 동작: `20260720_131207_863008_200_b`

보정된 이벤트 `timestamp_ns`와 RGB `rgb__timestamp_ns`를 사용했다. 각 표시 시점에서 과거 이벤트만 사용하며, 누적 구간은 `(현재 시각 − 누적 길이, 현재 시각]`이다. 미래 프레임은 사용하지 않는다. 비교 영상은 초당 10장으로 표시하지만, 이벤트를 고르는 기준은 각 RGB 프레임의 실제 타임스탬프다. 학습 입력의 갱신 주기를 10Hz로 제한한다는 뜻은 아니다.

이벤트는 원래의 960×720 좌표에서 인코딩했다. 비교판에는 종횡비를 유지해 축소 표시했고, 개별 이벤트 영상은 960×720을 유지했다. RGB 재투영, 사람 분할, 자세 모델 추론은 적용하지 않았다. 원본 데이터셋은 읽기만 했다.

현재 `event.npz`는 원시 비동기 이벤트 목록 자체가 아니라, 저장된 이벤트 프레임을 희소 행렬로 압축한 형식이다. 확인한 데이터의 값은 `−128`과 `+127`이며, 인코딩 메타데이터는 `int8(pixel - 128)`이다. 이번 계산에서는 부호만 이용해 양·음 극성을 같은 단위 가중치로 취급했다. 따라서 아래의 발생 횟수는 **저장된 프레임에서 해당 픽셀이 활성화된 관측 횟수**다. 한 원본 프레임 안에서 발생한 실제 이벤트 수와 개별 이벤트 시각은 복원할 수 없다.

## 각 인코딩에서 한 픽셀이 담는 정보

아래 표는 실제 생성 코드의 **표시 영상** 기준이다. 좌표 `(x,y)`는 이벤트 카메라의 픽셀이고, 양극성은 밝기 증가, 음극성은 밝기 감소 관측을 뜻한다. 인체 존재 확률·깊이·RGB 색을 나타내는 값이 아니다. `N+`, `N−`는 지정 구간에서 해당 픽셀의 양·음 **저장 프레임 활성 관측 횟수**다. `I(N)=sqrt(min(log(1+N)/log(9),1))`이며, 아래 RGB는 OpenCV 내부 BGR 저장순서를 RGB로 풀어 설명했다.

| 실제 표시 방식 | 시간 범위 | 한 픽셀이 담는 수치 | 화면 색상·밝기의 의미 | 표시에서 잃는 정보 |
| --- | --- | --- | --- | --- |

| 주변 지지 누적33ms | 최근33ms | 33ms 극성 분리 누적에 위와 같은3×3 공간 마스크 적용 | 현재 움직임의 극성·관측량을 표시하고 고립 점을 제거 | 제거된 희소 신호·구간 내부의 시간 순서 |

극성 분리 누적의 실제 RGB 합성은 `RGB=(p,0.25p+0.65n,n)`에255를 곱한 값이다. 여기서 `p=I(N+)`, `n=I(N−)`이다. 시간 표면도 같은 합성식을 쓰지만 `p=S+`, `n=S−`로 바뀐다. 따라서 표시 RGB3채널이 독립된 세 물리량이라는 뜻은 아니다. 누적은8회부터 밝기가 포화하며, 검정은 방식에 따라 무관측·극성 상쇄·필터 제거를 뜻할 수 있다.

보고서 후반의 **6채널·14채널은 학습 후보**이며, 위 실제 생성10설정과 구분한다. 6채널 후보의 한 픽셀은 `과거+/과거−/중간+/중간−/최근+/최근−` 관측량을 각각 보존한다. 14채널 후보는20ms 간격5구간의 극성별 관측량10개, 극성별 시간 표면2개,200ms 극성별 관측량2개다. 이 보고서 작성 당시 두 후보로 학습한 결과는 제시하지 않았다.

누적 횟수의 표시 밝기는 `sqrt(clip(log(1 + 횟수) / log(9), 0, 1))`로 고정했다. 프레임마다 최대 밝기를 다시 맞추지 않아, 희소한 장면에서 배경 잡음이 갑자기 밝아지는 효과를 피했다. 제곱근은 시각화의 감마 보정이며, 실제 학습에서는 정규화 방법을 별도로 비교해야 한다.

시간 표면은 극성마다 마지막 관측 시각을 저장하고 `exp(−경과 시간 / 감쇠 시간)`으로 표시했다. 최대 200ms 과거까지 사용했다. 20ms 설정에서 60ms 전 관측의 값은 약 0.05이므로, 오래된 팔 위치가 빠르게 희미해진다.

고립 점 제거는 활성 픽셀의 3×3 이웃에서 자신을 포함해 활성 픽셀이 2개 이상일 때 남기는 약한 필터다. 사람만 골라내는 분할기가 아니며, 손끝이나 멀리 있는 사람의 희소한 신호도 제거할 수 있다. 초기 확인에서는 같은 픽셀의 반복 발생까지 요구하는 강한 조건이 작은 얼굴 움직임의 신호를 과도하게 지웠다. 최종 영상에는 반복 발생 조건을 넣지 않았다.

## 윤곽과 자세 변화를 위한 추천 설정

### 확인용 영상

현재 자세의 윤곽을 볼 때는 **33ms 극성 분리 누적과 약한 고립 점 제거**를 기본으로 사용한다. 손과 팔의 빠른 변화는 **시간 표면 20ms**를 나란히 보고, 이동 순서는 **100ms를 3구간으로 나눈 모션 표시**로 확인한다. 움직임이 작은 부위는 100ms 누적을 보조로 사용한다.

200ms 누적을 단순히 밝게 표시하면 사람 형태가 풍부해 보일 수 있지만, 현재 관절 위치와 지난 위치가 섞인다. 선명해 보이는 실루엣과 자세 추정에 유리한 입력은 같은 기준이 아니다.

### 학습 입력

우선 구현할 작은 기준선은 **100ms를 3개 시간 구간으로 나누고 각 구간의 양·음 극성을 분리한 6채널 입력**이다. 영상에 표시한 시간 구간 표현의 색상 합성 대신, 극성별 누적 값을 그대로 모델에 넣는다. 시간 순서와 극성 상쇄 방지를 함께 다루면서 비교가 간단하다.

윤곽과 모션을 함께 보완하는 다음 후보는 아래의 **14채널 입력**이다.

| 입력 구성 | 채널 수 | 역할 |
| --- | --- | --- |
| 최근 100ms를 20ms씩 5구간으로 나눈 극성별 누적 | 10 | 짧은 구간의 윤곽과 이동 순서를 보존 |
| 극성별 시간 표면 | 2 | 감쇠 시간 20ms로 최근 움직임을 강조 |
| 최근 200ms의 극성별 누적 | 2 | 움직임이 작은 부위의 구조를 보완 |

긴 구간의 누적은 짧은 구간에 직접 합치지 않고 별도 채널로 둔다. 필요에 따라 모델이 참고하도록 하고, 빠른 동작에서는 긴 구간의 영향이 커지지 않도록 검증한다. 이 6채널·14채널 구성은 이번 시각 비교에서 도출한 **학습 후보**이며, 해당 입력으로 모델을 학습해 성능을 검증한 결과는 아니다. 5개 시간 구간이나 14채널이 최적이라는 결론도 아직 내리지 않는다.

원해상도에서의 희소한 점을 작게 축소할 때는 신호가 사라질 수 있다. 학습용 누적 표현은 목표 해상도의 픽셀에 관측 횟수를 합산한 뒤 정규화하는 방법을 우선 비교한다. 시간 표면은 최근 관측을 보존하는 축소 방식도 함께 검토한다. 영상의 표시용 축소 결과를 그대로 학습 데이터로 삼지 않는다.

RGB와 함께 사용할 경우에는 두 센서의 좌표계 차이를 처리해야 한다. RGB의 사람 영역을 이벤트 영상에 같은 픽셀 좌표로 잘라 붙이면 안 된다. 보정과 깊이를 이용한 재투영 또는 센서별 특징을 추출한 뒤의 융합이 필요하다.

## 정지 부위와 자세 추정에서 남는 문제

이벤트는 밝기 변화에 반응하므로, 움직이지 않는 다리나 몸통이 항상 완전한 외곽선으로 나타나지는 않는다. 긴 시간 누적만으로 이를 해결하면 이전 자세가 남는 문제가 생긴다. 정지 부위를 안정적으로 복원해야 한다면 시간에 따른 특징 기억, 인체 구조 제약, 허용되는 경우 RGB 정보 등을 함께 검토해야 한다. 이벤트에서 관측되지 않은 부분까지 인코딩만으로 항상 복원할 수 있다고 가정하지 않는다.

이번 두 세션의 60초 정성 비교는 입력 후보를 고르는 근거다. 사람 윤곽의 분할 정답을 이용한 정확도나 관절 위치 오차를 측정하지 않았으므로 수치 순위는 매기지 않았다. 실제 입력 선택에서는 같은 학습 조건으로 6채널 기준선과 14채널 후보를 비교하고, 빠른 팔 동작·느린 동작·정지 구간을 나누어 다음 항목을 확인하는 것이 적절하다.

- 윤곽 정답이 있는 경우 경계 일치도와 작은 부위의 보존율
- 관절 위치 오차와 빠른 동작에서의 추적 실패율
- 관절 속도 오차, 시간 지연, 정지 구간의 흔들림
- 입력 해상도와 채널 수에 따른 메모리 및 처리 속도

## 관련 연구와 이번 제안의 관계

시간을 한 장으로 합치지 않고 구간으로 나누는 방향은 [이벤트 복셀을 구성하는 E2VID 공식 구현](https://github.com/uzh-rpg/rpg_e2vid/blob/master/utils/inference_utils.py)에서도 확인할 수 있다. 이번 표시용 3구간 인코딩은 단순 구간별 누적이며, 해당 구현의 시간 보간 복셀을 그대로 구현한 것은 아니다.

인체 자세에 관한 [삼차원 이벤트 표현 연구](https://arxiv.org/abs/2311.04591)는 시간 구조를 보존하는 점군과 복셀 표현을 제안한다. [EventHPE](https://arxiv.org/abs/2108.06819)는 이벤트와 움직임 정보를 사용해 인체 자세와 형상을 추정한다. 이 연구들은 모션과 시간 구조를 입력에 남겨야 한다는 설계 방향의 근거이며, 이번 데이터에서 제안한 누적 길이나 채널 수의 성능을 보증하지는 않는다.

## 재현과 산출물

실행 코드는 [이벤트 인코딩 비교 도구](/home/namhj/EventPose/tools/compare_event_encodings.py)에 있다. 최종 계산에는 `.venv-humanpose/bin/python`을 사용했다. 기본 전신 비교와 추가 전신 비교는 다음과 같이 재현한다.

```bash
.venv-humanpose/bin/python tools/compare_event_encodings.py \
  dataset/20260720_131207_863008_200_b/device0 \
  exp/261024/event_encoding_comparison/body

.venv-humanpose/bin/python tools/compare_event_encodings.py \
  dataset/20260720_131207_863008_200_b/device0 \
  exp/261024/event_encoding_comparison/body_refined --refine
```

각 출력 폴더의 `settings.json`에 시간 구간, 정규화, 극성 처리와 필터 조건을 기록했다. 비교 영상은 1440×1176, 개별 이벤트 영상은 960×720이며 모두 60초·10fps의 H.264 형식이다.
