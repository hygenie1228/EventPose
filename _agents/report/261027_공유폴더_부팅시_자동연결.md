# 공유폴더 부팅 시 자동 연결

현재 /home/namhj/share는 147.46.76.228:/home/namhj/share의 NFS v3, /mnt/nfs_L은 147.46.174.20:/mnt/storage의 NFS v4.2 마운트다. /etc/fstab에는 두 항목이 등록되어 있지 않다.

현재 연결 버전을 유지한 설정안을 _agents/research/261027/nfs_autostart.fstab에 준비했다. findmnt --verify --tab-file 검사에서 오류와 경고가 없었다. 실제 /etc/fstab은 변경하지 않았으며 재부팅 검증도 하지 않았다. 이 세션은 sudo 비밀번호가 필요하므로 관리자 설정은 사용자가 터미널에서 적용해야 한다.

/etc/fstab을 백업한 뒤 다음 두 줄을 한 번만 추가한다.

```fstab
147.46.76.228:/home/namhj/share /home/namhj/share nfs rw,vers=3,proto=tcp,hard,_netdev,nofail,x-systemd.mount-timeout=60s 0 0
147.46.174.20:/mnt/storage /mnt/nfs_L nfs rw,vers=4.2,proto=tcp,hard,_netdev,nofail,x-systemd.mount-timeout=60s 0 0
```

```bash
sudo cp -a /etc/fstab /etc/fstab.backup-261027
sudoedit /etc/fstab
sudo systemctl daemon-reload
sudo mount -a -t nfs,nfs4
findmnt -T /home/namhj/share
findmnt -T /mnt/nfs_L
```

재부팅 시 네트워크 준비 후 마운트를 시도한다. nofail은 원격 서버 연결 실패가 시스템 부팅 실패로 이어지는 것을 방지한다. 마운트 작업 제한은 60초다. 부팅 당시 원격 서버가 응답하지 않으면 연결을 보장하지 않으며, 복구 후 수동 재시도가 필요할 수 있다. 현재 두 경로는 이미 연결되어 있으므로 mount -a 성공만으로 다음 부팅의 연결까지 검증한 것은 아니다.

참고: https://www.freedesktop.org/software/systemd/man/latest/systemd.mount.html
