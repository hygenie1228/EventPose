## 초록

이벤트는 움직임을 관측하지만, 관측량이 많다는 사실이 정확한 3D 운동 정보를 보장하지는 않는다. 특히 RGB 복원기의 실행 사이 간격이 길 때, 정지 부위에서 관측이 희박할 때, 과거 이벤트가 오래 누적될 때 각 모달리티의 신뢰도는 관절과 시각에 따라 달라진다. 본 제안은 기존 RGB 인체 복원기를 재사용하면서, 이벤트로 예측한 동작 변화와 과거 상태를 **관측 품질에 조건화한 불확실성**으로 결합한다. 사용자 설명에 따르면 빠른 동작과 자연 blur는 이 데이터에 드물다. 따라서 주목표를 **낮은 RGB 호출률에서 이벤트가 RGB-only 시간 예측보다 동작 품질을 잘 유지하는지**로 수정한다. 총 처리 비용과 출력 지연을 함께 측정하고, 적응적 RGB 호출은 고정 주기 비교가 통과한 뒤 확장한다.

Train 내 6명의 짧은 전신 구간을 이용한 선형 진단에서는 이벤트 관측량과 속도의 상관이 높았지만, 이벤트 특징 추가가 골반 정렬 관절 오차를 줄이지 못했다. 따라서 본 연구의 출발점은 단순 융합의 이득이 아니라 **잘못된 이벤트 갱신을 줄일 수 있는가**이다.

## 1. 연구 질문과 동기

**같은 RGB 모델과 호출 시각을 사용할 때, 중간 이벤트 갱신이 RGB-only 시간 예측보다 정확한가? 그 이득이 이벤트 처리 비용을 감수할 만큼 크며, 관측 품질 조건화가 고정 융합보다 나은가?**

예를 들어 빠르게 움직이는 손목에는 최근 이벤트가 유용할 수 있지만, 거의 정지한 몸통에서는 과거 상태가 더 안정적일 수 있다. 반대로 이벤트가 적다는 이유로 상태를 무조건 고정하면 가려진 사람의 움직임을 놓친다. 관측 부족은 “정지 확정”이 아니라 “모른다”로 처리해야 한다. RGB 처리 사이에 실제 움직임이 생겼을 때만 이벤트가 유효한 새 정보를 주는지 확인한다. RGB-only로 충분한 구간에서는 이벤트를 무조건 추가하지 않는다.

이 주제가 가장 실행하기 좋은 이유는 저장소에 RGB Multi-HMR, 이벤트 인코딩, 카메라 보정, GT 및 평가 코드가 이미 있기 때문이다. 처음에는 기존 복원기를 동결하고 작은 시간 보정기만 학습한다. 큰 motion foundation model을 새로 학습하거나 원시 이벤트를 복원할 필요가 없다. 이는 구현 난이도에 대한 판단이며 성능 성공 확률을 수치로 보장하는 말은 아니다.

특히 [E-3DPSM 원문 4.2절](https://arxiv.org/html/2604.08543v1)은 공분산을 유지하고 Q/R도 학습한다. 이를 “불확실성을 사용하지 않는 방법”으로 설명하면 잘못이다. **추론 때 관측 상태에 맞춰 변하는 신뢰도와 그 실제 보정 효과**가 본 제안의 좁은 차별점이다. 조건화만 추가해서 기여가 충분한지는 실제 절제실험으로 판단해야 한다.

## 3. 제안 방법

### 3.1 입력과 출력

입력은 현재 시각까지의 이벤트, 현재까지 도착한 RGB, 카메라 보정과 이전 예측 상태다. 출력은 공통 카메라 좌표계의 body22 관절과 관절별 위치 불확실성이다. 첫 버전은 관절 복원에 집중하고, SMPL-X 전체 mesh는 결과가 확인된 뒤 확장한다.

RGB와 이벤트는 다른 카메라다. 특징을 같은 픽셀에서 바로 합치지 않는다. 이전 **예측** 3D 관절을 이벤트 카메라에 투영해 주변 특징을 수집하고, 투영 오차에 대비해 여러 반경 또는 넓은 탐색 특징을 사용한다. GT 관절 위치를 입력 crop이나 attention 위치로 쓰지 않는다.

### 3.2 관측 품질 조건화

이벤트 품질 벡터에는 최근 관측의 나이, 극성별 특징, 시간 구간 간 일관성, 공간적 집중도, 이전 예측과의 잔차를 넣는다. RGB에는 관절 주변 특징 품질과 마지막 RGB 이후 경과 시간을 넣는다. 단순 Laplacian sharpness나 이벤트 count 한 개로 신뢰도를 결정하지 않는다. 센서 시간 구간 자체가 없는 경우는, 유효 구간에서 해당 부위에 이벤트가 없는 경우와 별도 마스크로 구분한다.

관절 j의 예측과 갱신을 다음처럼 시작할 수 있다.

\[
\mu^-_{t,j}=f(\mu_{t-1},v_{t-1},\Delta t),\qquad
P^-_{t,j}=P_{t-1,j}+\Delta t\,Q_{t,j},
\]

\[
Q_{t,j}=\operatorname{diag}(\operatorname{softplus}(q(h_{t,j}))+\epsilon),\quad
R^E_{t,j}=\operatorname{diag}(\operatorname{softplus}(r(h_{t,j}))+\epsilon).
\]

여기서 h는 현재까지의 관측 품질과 상태 특징이다. 이벤트로 얻은 관절 위치 관측을 z로 두고, 대각 공분산의 간단한 필터로 결합한다. delta를 사용할 경우에는 과거 상태와의 상관 때문에 같은 정보를 이중 계상하지 않도록 별도 절제실험을 둔다. RGB 관측이 도착하면 RGB용 공분산으로 추가 갱신한다. 초기에 대각 행렬을 쓰는 것은 구현 선택이며 새로운 필터 이론이라는 주장은 하지 않는다.

관측이 사라져도 Q를 0으로 고정하지 않는다. 상태 평균은 보수적으로 예측하되 불확실성을 유지·증가시켜 숨은 움직임을 확정적으로 부정하지 않는다. 다중 인물의 ID 연결이 불안정할 때는 같은 상태로 이어 붙이지 않는다.

### 3.3 학습과 불확실성 보정

3D 관절 오차, 속도 오차, 관절별 Gaussian 또는 Laplace 음의 로그우도, 뼈 길이 제약을 결합한다. 분산을 키워 오차를 숨기는 해법을 막기 위해 로그 분산 항을 포함한다. 관측 삭제·잡음·시간 오프셋 교란은 Train에서만 생성한다. 단순 관측 dropout이 실제 가림과 동일하다고 가정하지 않는다.

신뢰도는 별도 피험자 검증에서 50/80/95% 구간 포함률, 구간 폭, risk–coverage 곡선으로 평가한다. 평균 오차가 좋아도 불확실성이 틀리면 “신뢰도 개선”을 주장하지 않는다.

### 3.4 RGB 재관측은 2단계 확장

기본 보정기가 통과한 뒤, 일정 예산 내에서 예측 불확실성이 커질 때 RGB 복원기를 호출한다. 초기 구현은 token bucket과 최소/최대 호출 간격으로 충분하다. 일정 주기 호출, 이벤트 count 기반 호출, 무작위 호출을 같은 실현 호출 수에서 비교한다. RGB를 덜 **처리**하는 것과 센서가 덜 **촬영**하는 것을 구분하고, 전자는 센서 전력 절감으로 주장하지 않는다.

## 4. 실제 데이터 예비실험

### 4.1 범위와 재현 조건

전신 Train 세션 6개, 피험자 200/201/202/207/208/101에서 시작 후 약 1~21초를 10Hz로 읽었다. 피험자마다 200개 시점을 만들고 직전 두 시점을 필요로 하는 1단계 진단은 총 1,188개다. 사람을 하나씩 제외해 학습/평가했으며 Test 데이터와 신경망 학습은 사용하지 않았다. 직전 두 **GT 자세를 제공한 oracle 조건**이므로 아래 숫자는 실제 배포 tracking 성능이 아니다. Ridge 규제값 100은 고정했다.

| 진단 방법 | 절대 관절 오차 (mm) | 골반 정렬 관절 오차 (mm) | RPE-Z (mm) |
|---|---:|---:|---:|
| 이전 GT 자세 유지 | 44.24 | 39.31 | 13.95 |
| 이전 GT 속도로 등속 외삽 | 40.32 | 35.53 | 13.65 |
| 과거 자세·속도 선형 회귀 | 32.19 | **27.74** | **11.26** |
| 과거 자세·속도 + 이벤트 특징 회귀 | **32.01** | 28.68 | 11.36 |
| 이벤트 특징을 시간 이동한 대조군 | 36.36 | 31.55 | 12.69 |

표는 이 작은 진단 안에서만 열별 최저값을 표시했다. 본 저장소의 전체 Test 주표와 평가 조건이 달라 직접 비교할 수 없다. RPE-Z는 정렬 전 root Z 차이의 절댓값이며 full 3D root distance가 아니다.

![선형 모션 예비실험](/home/namhj/EventPose/exp/261026/idea_motion_probe/선형_모션_진단.png)

33ms 전역 관측 수와 GT 평균 관절 속도의 세션별 Spearman 상관은 약 0.775~0.945였다. 그러나 골반 정렬 오차는 이벤트 추가 시 약 0.94mm 악화했다. 시간 이동 대조군보다 나은 결과는 시간적 연관성의 단서이지만, 전체 3D 추정의 개선 증거는 아니다. 반복 동작과 공통 촬영 조건의 영향도 배제하지 못했다.

피험자 단위 10,000회 재표집으로 이벤트 추가−과거 정보만 사용의 차이를 탐색적으로 확인했다. 절대 오차 차이는 −0.18mm이고 95% percentile 구간은 −1.47~+1.11mm, 골반 정렬 오차 차이는 +0.94mm이고 구간은 −0.27~+2.08mm였다. 두 지표 모두 개선된 피험자는 6명 중 2명이었다. 6명과 상호 겹치는 학습 fold의 작은 진단이므로 확증적 유의성 검정으로 해석하지 않는다. ### 4.2 관측량을 신뢰도로 쓰기 어려운 이유

별도 원해상도 진단에서 상체 두 세션의 33ms 관절 주변 활성 비율 중앙값은 1.96%/1.84%, 배경 구석은 2.05%/2.02%였다. 전신 두 세션은 관절 부근 30.28%/34.59%, 배경 약 2.04%였다. 동일한 count 규칙을 서로 다른 장면에 그대로 적용하기 어렵다.

이 수치는 GT 관절을 투영한 41×41 패치의 고유 활성 픽셀 비율이다. 관절 중심이 이벤트 윤곽과 다를 수 있고, 배경 관측은 실제 배경 변화나 센서 특성을 포함한다. 이 진단만으로 잡음률·가림률·가시성을 추정하지 않는다.

## 5. blur와 latency 중 무엇을 주기여로 둘 것인가

**수정된 우선순위는 낮은 RGB 처리 예산에서의 동작 정확도와 총 처리 비용이다.** 사용자가 빠른 동작·자연 blur가 드물다고 설명했으므로, 이를 주목표로 삼았던 초기 추천을 철회한다. 그 사실만으로 latency 개선이 자동으로 입증되는 것은 아니다.

고정 RGB 호출률별로 RGB-only와 event 보정의 정확도–총 처리 비용 곡선을 먼저 비교한다. 예를 들어 검증에서 2/5/10Hz 호출 조건을 정하고, 같은 RGB 입력만 사용하는 상태 유지·등속 예측·인과적 시간 모델을 강한 기준선으로 둔다. 현재 시각 이후 RGB를 읽는 보간은 인과적 방법과 같은 조건으로 비교하지 않는다. 기존 RGB를 덜 처리하는 실험은 촬영 속도나 센서 전력 절감 실험과 구분한다.

느린 동작에서는 RGB-only 시간 예측이 이미 충분할 수 있다. event 전처리·보정 비용까지 포함했을 때 이득이 없으면 이 연구의 실용적 전제가 성립하지 않는다. 현재 선형 진단은 GT 앵커를 매 시점 제공했으므로 낮은 RGB 호출률의 폐루프 결과를 대신하지 않는다.

아래 합성 blur 그림은 이미 수행한 인공 영상 열화 예시를 보존한 것이다. 자연 blur가 드문 이 데이터에서 주실험이나 실제 이벤트 이득의 증거로 사용하지 않는다. 실제 노출 적분을 재현한 결과도 아니다.

![합성 blur 대조 예시: 각 행 왼쪽 원본, 중앙 15픽셀, 오른쪽 31픽셀](/home/namhj/EventPose/exp/261026/idea_motion_probe/synthetic_blur_controls.jpg)

이벤트 센서의 픽셀 지연은 광량과 설정 등에도 의존한다. 센서 사양을 모델 출력 지연으로 대체하지 않는다. [NIST의 Pixel Latency Measurements, 2025](https://www.nist.gov/publications/pixel-latency-measurements-event-cameras)도 재현 가능한 센서 지연 측정 조건의 필요성을 다룬다.

CPU에서 224×224 표현을 생성한 20시점의 전처리 측정은 다음과 같다. 각 표현 1회 워밍업 후 측정했으며 디스크·센서·HMR·GPU·전송은 제외했다.

| 표현 | 중앙값 (ms) | p95 (ms) |
|---|---:|---:|
| 최근 프레임 회색조 | **1.35** | **1.37** |
| 극성 분리 33ms 누적 | 1.79 | 2.92 |
| 100ms의 3구간 극성 분리 | 5.21 | 8.01 |
| 20ms 감쇠·200ms 이력 시간표면 | 38.36 | 59.64 |

이는 현재 CPU 구현과 한 짧은 세션에 대한 측정이다. 최적화된 GPU·증분 시간표면 구현의 비용을 대표하지 않는다. GPU HMR을 포함한 최종 latency 순위도 아니다.

과거 [t−W,t]만 사용하는 sliding window는 정상 운용에서 W만큼 추가로 기다려야 한다는 뜻이 아니다. 시작 시 버퍼 확보, 출력 주기, 입력 전송, 전처리, 추론, 미래 관측 대기, 오래된 관측에 의한 동작 반응 지연을 각각 측정한다. 처리량 fps가 높아도 최신 출력이 늦을 수 있다. [Event-Based Vision: A Survey](https://doi.org/10.1109/TPAMI.2020.3008413)는 이벤트별·묶음 처리의 지연 차이를 논의한다.

## 6. 본실험 설계와 판정 기준

비교는 RGB-only, RGB+단순 평활화/등속 예측, 고정 Q/R 보정, 조건화 Q/R 보정, 조건화에서 품질 특징 제거, 이벤트 시간 순서 교란을 포함한다. 기본 RGB 복원기·학습 표본·입력 해상도·출력 시각·RGB 예산은 동일하게 둔다. E-3DPSM의 핵심 결합도 같은 exocentric 설정으로 재현한 비교군을 준비하고, 논문의 egocentric 수치를 그대로 옮겨 비교하지 않는다.

정상 촬영의 RGB 호출률별 비교를 주실험으로 한다. 호출률을 낮춘 RGB-only에도 같은 학습 기회와 강한 인과적 temporal baseline을 제공한다. 이벤트 저관측, 입력 dropout, 시간 오프셋은 보조 실험으로 분리한다. 합성 blur는 선택적 보조 실험이며 이를 위해 주실험의 문제 정의를 바꾸지 않는다. 모든 호출률·허용 오차·설정은 Test 전에 고정한다.

최종 자세 주표는 동일 공통 GT/검출 표본에서 10초 구간의 first-frame MPJPE/PA-MPJPE, frame-aligned MPJPE/PA-MPJPE, RPE-Z 다섯 지표를 mm로 보고한다. first-frame 변환은 정확한 frame0에서만 구해 고정한다. 별도로 속도 오차(mm/s), 가속도 오차(mm/s²), 빠른 손목의 peak 속도 보존, 검출률·추적 단절, 불확실성 보정, end-to-end p50/p95 지연과 deadline 실패율을 보고한다. 단순 평활화로 peak를 없앤 결과를 모션 개선으로 판정하지 않는다.

정식 학습 전에는 실제 `split.json`의 형식과 피험자 분리를 다시 검증한다. 이번 파일은 train이 목록, test가 세션별 구간 사전이라 과거의 두 목록 형식과 다르다. 이번 probe는 파일 스냅샷과 선택한 Train 세션을 사용했으며 공식 분할 전수 검증을 대신하지 않는다.

**첫 go/no-go:** 먼저 새 피험자·새 시간 구간에서 같은 낮은 RGB 호출률의 강한 RGB-only 예측보다 event 보정이 유용한지 확인한다. 그 다음 고정 Q/R보다 관측 조건화의 오차 또는 risk–coverage가 개선되는지 본다. 이벤트 전체 경로의 비용까지 포함해 비교한다. 최소 이득과 허용 손상폭은 Test 전에 정한다. 개선이 단순 평활화나 RGB-only 시간 모델로 설명되면 이 주제의 주장을 축소한다. 전신 정상 장면의 현재 예비결과만으로 이벤트 효용을 이미 확보했다고 말하지 않는다.

## 7. 구현 순서와 예상 범위

1. 실제 분할·타임스탬프와 고정 RGB 호출 시각을 정하고, RGB-only의 상태 유지·등속·인과적 예측 기준선을 준비한다.
2. 가벼운 event 보정이 동일 RGB 호출률의 기준선을 넘는지 확인한 뒤, 고정 Q/R과 관측 조건화 Q/R을 비교한다. 처음부터 적응적 호출 정책까지 함께 학습하지 않는다.
3. 정상 동작에서 호출률별 정확도·총 비용·출력 지연과 정지/재움직임 반응을 평가한다. 관측 누락 등의 강건성은 별도 확인한다.
4. 통과하면 RGB 호출 예산 및 mesh로 확장한다.

기존 코드와 자원이 정상이라는 가정에서 첫 구현·작은 검증은 약 2~4일, 논문 수준 비교는 수 주 규모로 예상한다. 실제 wall time 약속이나 이번 요청에서 후속 학습을 실행했다는 뜻은 아니다.
