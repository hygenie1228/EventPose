# RGB와 이벤트 입력 검증

device0 전283세션의 이벤트 메타데이터와 카메라 보정을 읽기 전용으로 검사했다. 모든 세션에서 label.h5의 source_rgb_timestamp_ns와 event.npz의 rgb__timestamp_ns[원본프레임번호] 대응이 일치했다.

| 구분 | 세션 수 | 요청 프레임 | event 관측 가용 프레임 | event 미가용 프레임 |
|---|---:|---:|---:|---:|
| 학습 | 187 | 116146 | 115838 | 308 |
| 내부 검증 | 32 | 2048 | 2045 | 3 |
| Test | 64 | 96124 | 96040 | 84 |

가용성은 RGB 기준 시각 이하의 최근 저장 event 프레임이 있고 그 간격이20ms 이하인 경우다. 저장 이벤트가 없는 픽셀과 센서 시간 구간 자체가 없는 경우를 구분한다. 미가용 Test 프레임을 임의로 삭제하거나 미래 event로 채우지 않는다.

카메라 보정에서 RGB와 event의 위치 차이는 약47.17mm다. RGB/event를 같은 픽셀로 간주하는 중첩 또는 GT 깊이를 이용한 입력 정렬은 사용하지 않는다. event-only는 event 좌표계에서 예측한 결과를 알려진 보정으로 RGB 평가 좌표계에 변환한다. RGB+event는 별도 event encoder와 광선/카메라 원점을 사용하는 특징 결합을 준비했다.

네 인코딩:33ms 극성별 로그 누적2채널,100ms3구간×2극성6채널,20ms감쇠·200ms과거의 극성별 시간표면2채널,visualize_data.py 회색조1채널이다. 기본 캐시 크기는224×224이며 종횡비와 패딩 좌표변환을 보존한다. 누적은 축소 픽셀에 관측을 더한 후 정규화하고 시간표면은 최근 관측을 보존한다. 회색조는 원해상도에서 배경128/양255/음0을 만든 후 INTER_AREA로 축소한다. 압축MP4는 학습 입력으로 사용하지 않는다.

CPU 자기검사에서 인과적 시간창,극성 보존,정수타임스탬프 정밀도,시간표면 감쇠,회색조 재현,미가용 입력을 확인했다. 융합 모듈의 보정광선,초기 RGB 모델과 동일 출력,유효 gradient,미가용 event 시 RGB fallback도 확인했다. 아직 이 모듈로 학습 성능 향상을 검증한 것은 아니다.

수치 채널은 uint8로 캐시하고 읽을 때255로나눈다. 누적 정규화는 log1p(count)/log1p(256)을0~1로제한하며 프레임마다 최대값으로 재정규화하지 않는다. 저장 카운트는 원시 이벤트 발생 횟수가 아니다. 설정 지문·원본ZIP CRC와 크기/수정시각 지문·보정·프레임매핑을 캐시에 함께 기록한다.
