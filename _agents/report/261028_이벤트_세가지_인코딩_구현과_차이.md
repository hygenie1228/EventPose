# Event Encoding: count33, bins100 and surface20

| Encoding | Channels | Causal observation window | Information retained |
|---|---:|---|---|
| count33 | 2 | Last 33 ms | Polarity-separated observation count |
| bins100 | 6 | Last 100 ms, divided into three time bins | Coarse temporal order and polarity |
| surface20 | 2 | Last 200 ms, with a 20 ms decay constant | Recency of the latest observation per polarity |

## Actual data and common preprocessing

The source is the stored sparse event-frame archive event.npz, not an original list of independently timed raw events. timestamp_ns gives each stored frame's corrected timestamp; indptr identifies its sparse-array interval; indices gives active pixel locations; the sign of data specifies polarity. data > 0 is positive. Its magnitude is not interpreted as an event count. Within-frame raw event multiplicity and timing are unavailable.

All methods use a common corrected reference timestamp t and include only observations at or before t. Original event coordinates are mapped to an aspect-preserving 224 x 224 grid with zero padding. Several native pixels can map to one output cell. RGB and event pixels are not assumed to coincide. Sensor-specific intrinsics and extrinsics are retained for later feature fusion.

## count33: observation quantity

The interval is (t - 33 ms, t]. For each output pixel and each polarity, N is the number of stored active-pixel observations mapped into that cell. The two-channel output is [positive, negative].

```text
count33 = min(log(1 + N) / log(257), 1)
```

Zero observations gives 0; one gives approximately 0.125; two gives approximately 0.198; 256 or more saturates at 1. Temporal order within the window is discarded.

## bins100: coarse temporal order

The last 100 ms is divided into three approximately equal 33.33 ms bins. Each bin independently computes the same polarity-separated log-count formula. Channel order is [old positive, old negative, middle positive, middle negative, recent positive, recent negative]. The actual network input has six channels.

The integer-nanosecond edges are t - 100000000 + floor(k * 100000000 / 3), k = 0, 1, 2, 3. Each interval excludes its left boundary and includes its right boundary. The slight difference between a 33 ms count33 window and a 100/3 ms temporal bin is intentional. Temporal order is retained between bins, but not within a bin.

## surface20: observation recency

For each output pixel and polarity, find the latest stored observation t_last in (t - 200 ms, t].

```text
surface20 = exp(-(t - t_last) / 20 ms)
No observation: 0
```

The name refers to the 20 ms decay constant, not a 20 ms collection window. Values after 0, 5, 20, 40 and 100 ms are approximately 1, 0.7788, 0.3679, 0.1353 and 0.0067. Only the latest observation matters. Native pixels merged into one output cell contribute their latest timestamp. Timestamp subtraction is performed in signed int64 before conversion to floating-point relative time.

## Storage, augmentation and network gains

The computed float values are quantized as round(255 * value), stored as uint8 in losslessly compressed HDF5, and divided by 255 when loaded. Quantization is a separate step and can erase extremely small surface values. Online evaluation uses the same quantization for input parity.

Training augmentation multiplies the input by a shared random gain in [0.9, 1.1] and clips to [0, 1]. The auxiliary event CNN then applies the same fixed input gain 4 for every encoding. For an event primary, the linear projection receives the unscaled event values, while the local refiner receives gain-4 values. These gains are separate from the encoding definition and are not fitted to Test performance.

## Unified visualization convention

![Reference-style event visualization](/home/namhj/EventPose/exp/261028/device3_encoding_12h/encoding_explanation/editable/pptx_preview/slide-2.png)

The displayed RGB composites follow the user-specified event comparison convention: black background, orange-red positive polarity and cyan negative polarity, fixed sqrt(min(log1p(N)/log(9), 1)) count brightness, and weak 3 x 3 neighborhood support for the count33 contour. The support rule retains an active pixel when at least two pixels, including itself, are active in its neighborhood.

The time-surface display uses the same polarity colors and exponential decay. The bins100 display maps the oldest, middle and latest bins to red, green and blue, collapsing polarity only for display. Actual training retains six separate channels. Display colors, display gamma and contour support are not changes to training encodings or checkpoints.

The images use the same source frame and corrected timestamp for device3 and device4. Original sensor aspect ratios are preserved. Displayed examples are actual causal sparse observations; they are not synthetic event data.

## Availability and verification

A sensor is unavailable when no past stored event frame exists or the latest one is more than 20 ms old. This availability limit is distinct from surface20's decay constant. An unavailable event primary yields a missed detection; an unavailable auxiliary sensor masks its fusion residual.

All 78 experiment sessions and both sensors were checked for channel/frame/timestamp consistency. At three actual timestamps per sensor/session, all three encodings were recomputed from the source archive and matched the stored cache exactly. New HDF5 files were hashed in full. This validates the defined stored-observation encodings, not recovery of original per-event timestamps or multiplicities.
