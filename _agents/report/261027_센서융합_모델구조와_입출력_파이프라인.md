# 신체 동작 센서융합의 모델 구조와 입출력 파이프라인

작성 기준: 2026-10-27 한국시간(KST). 현재 재실험의 `epipolar_repair_norm_v2` 구현을 설명한다. 도식은 실제 코드와 설정을 대조해 작성했으며 성능 향상을 입증하는 결과 그림은 아니다. 본학습과 전체 Test 결과는 [실험 보고서](261027_센서융합_열화원인_분석과_재실험.md)에서 별도로 갱신한다.

## 전체 모델 구조

![논문 Figure 2 형태의 센서융합 모델](../../exp/261027/device34_fusion_repair_15h/figures/신체센서융합_논문형_전체구조.png)

**그림 1. 보정 기반 센서융합 Multi-HMR.** [Multi-HMR 논문 Figure 2](https://www.ecva.net/papers/eccv_2024/papers_ECCV/papers/03364.pdf#page=3)의 가로 흐름을 참고해 새로 그렸다. 주 입력은 ViT를 거쳐 검출 token과 human query를 만들고, HPH가 pose·shape·translation을 복원해 SMPL-X mesh를 출력한다. 아래 주황색 분기는 독립 event CNN과 보정 기반 ray attention이며, 기존 주 특징에 잔차를 더한다. 파란색은 기존 Multi-HMR, 주황색은 추가 분기다. `C`는 내참수 Fourier 특징과의 concatenation이다. 아래쪽 전체 token은 HPH의 keys/values로 들어간다.

대표 입력·검출 score·mesh는 고정 Train 프레임에서 기존 Train-selected 가중치를 초기화로 삼은 추가학습 전 모델을 CPU 추론한 실제 예시다. 표의 배포 원본0 update 모델과 구분한다. 새 fine-tuning 완료 모델이나 Test 성능 예시가 아니다. token 색과 coarse 격자는 구조를 보여주는 도식이며 실제 다중 인원 검출 수를 뜻하지 않는다. event-only에서는 주 RGB 입력 대신 event adapter 출력을 사용하며 RGB 픽셀을 읽지 않는다.

발표·논문 편집용: [SVG](../../exp/261027/device34_fusion_repair_15h/figures/신체센서융합_논문형_전체구조.svg) · [PDF](../../exp/261027/device34_fusion_repair_15h/figures/신체센서융합_논문형_전체구조.pdf) · [PNG](../../exp/261027/device34_fusion_repair_15h/figures/신체센서융합_논문형_전체구조.png).

이 모델은 개별 프레임을 처리한다. 10초는 평가 구간 단위이며, 시계열 네트워크 입력 길이가 아니다. 두 카메라의 대응점을 삼각측량하는 별도 stage나 측정 depth 입력은 없다.

## 조건별 실제 센서 연결

조건 이름에 쓰인 장치 순서와 backbone의 주 입력 순서를 구분해야 한다. RGB가 포함된 수정법은 해당 RGB의 기존 검출·복원 경로를 유지한다.

| 비교 조건 | 주센서 → Multi-HMR | 보조센서 → fusion | 입력 adapter |
|---|---|---|---|
| device3 RGB | RGB3 | 없음 | RGB 정규화 |
| device4 RGB | RGB4 | 없음 | RGB 정규화 |
| device3 RGB + device4 event | RGB3 | event4 | 주 입력은 RGB 정규화 |
| device3 event + device4 RGB | **RGB4** | **event3** | 주 입력은 RGB 정규화 |
| device3 event + device4 event | event3 | event4 | event3 전용 공간 adapter |
| device3 RGB + device3 event | RGB3 | event3 | 주 입력은 RGB 정규화 |
| device4 RGB + device4 event | RGB4 | event4 | 주 입력은 RGB 정규화 |

기존 `event3 + RGB4` 구현은 event3를 주 입력으로 쓰고 RGB4를 작은 보조 CNN으로 처리했다. 수정법은 RGB4 단독이 갖고 있던 고해상도 사전학습 경로를 보존한다. 두 RGB 대조군은 각각 해당 융합법과 같은 출처 checkpoint에서 출발한다. event-only는 학습·검출·추론에서 RGB 픽셀을 읽지 않는다. RGB로 사전학습된 가중치의 사용과 현재 관측 RGB 픽셀의 사용은 별개다.

## 입력과 중간 tensor

아래 `B`는 batch 크기이며 현재 본학습은16이다. 모든 공간 크기는 전처리를 반영한 모델 입력 기준이다.

| 위치 | 실제 입력·출력 | 처리 |
|---|---|---|
| RGB 주 입력 | `B×3×896×896` | 원본 전체 프레임의 비율 유지 resize·letterbox 후 ImageNet mean/std 정규화 |
| event 입력 | `B×2×224×224` | count33의 양·음 극성 분리; uint8 캐시를255로 나눈 값 |
| event 주 입력 adapter | `B×2×224×224 → B×3×896×896` | 기존1×1 projection + 새 공간 refiner, bilinear 확대 후 ImageNet 정규화 |
| Multi-HMR backbone | `B×4096×1024` | DINOv2 ViT-L/14, 896/14=64이므로64×64 token |
| 보조 event CNN | `B×128×28×28` | gain4 → Conv/GroupNorm/GELU 세 단계; 채널32→64→128, 단계마다 stride2 |
| 기하 query grid | `B×256×1024` | 주 특징을16×16으로 pooling하고 query 생성 |
| 광선별 후보 | query당11개 | 카메라 Z 후보0.5, 0.75, 1, 1.5, 2, 2.5, 3, 4, 5, 6, 8m |
| 잔차 출력 | `B×4096×1024` | 후보 특징 attention → zero-init linear →16×16에서64×64 보간 |

count33은 보정된 기준 시각 `t`에 대해 **`(t−33ms, t]`**의 저장 희소 event 관측만 모아, 극성별 픽셀 관측 수 `c`를 `min(log(1+c)/log(257), 1)`로 변환한다. 이는 저장된 희소 프레임의 관측 집계이며 센서 원시 event 각각의 실제 발생 횟수·개별 시각을 복원했다는 뜻이 아니다. 미래 관측, event MP4, `frame_idx×50` 같은 가정은 사용하지 않는다.

gain4는 고정 Train6,501프레임의 비영 encoded pixel 중앙값32/255에서 정한 고정값이다. 새 보조 encoder와 공간 refiner에 적용하고, 검증된 기존 주 입력 projection은 원래 스케일을 유지한다. refiner의 마지막 convolution은0으로 초기화해 기존 event 주 입력을 처음부터 바꾸지 않는다.

## 보정 기반 fusion의 계산

RGB와 event의 같은 픽셀 위치가 같은 공간점을 본다고 가정하지 않는다. 주센서 내참수 `Kp`, 보조센서 내참수 `Ka`, 주센서에서 보조센서로의 외부 보정 `R, t`를 사용한다. 내참수에는 각 센서의 resize·padding 및 주 입력 확대를 반영한다.

주 query 픽셀 `u`를 역투영한 광선을 Z 성분이1이 되도록 정규화하고, 후보 `z`마다 다음 점을 만든다.

```text
r(u) = normalize_Z(Kp⁻¹ [u_x, u_y, 1]ᵀ)
Xp(z) = z · r(u)
Xa(z) = R · Xp(z) + t
ua(z) = project(Ka · Xa(z))
```

`ua(z)`에서 보조 event 특징을 bilinear sampling한다. 실제 CNN 특징 중심이 입력 픽셀0, 8, 16, …에 위치하므로 입력 픽셀 좌표를8로 나누어 특징 격자에 대응시킨다. 이미지 범위 밖이거나 보조 카메라 뒤에 있는 후보는 마스킹한다. 유효 후보가 전혀 없는 query는 잔차0으로 처리한다.

주 특징에서 생성한 query와 후보 event 특징의 내적으로 attention을 계산해 광선별 메시지를 만들고, 주 특징 차원의 잔차 `ΔF`로 바꾼다.

```text
F_fused = F_primary + auxiliary_available · ΔF
```

마지막 linear를0으로 초기화하므로 처음에는 정확히 기존 주 경로와 같다. 보조 입력이 가용하지 않으면 학습 후에도 주 특징을 그대로 사용한다. 후보 Z들은 **기하 샘플링을 위한 가설**이며 GT depth, 측정 depth, 최종 예측 depth가 아니다. 최종 사람 위치와 depth는 Multi-HMR head가 추정한다.

## 검출·복원 출력과 좌표

융합된64×64 token은 기존 Multi-HMR의 사람 검출과 HPH head에 들어간다. 추론에서는 score threshold0.3과3×3 NMS로 사람을 검출하고, 내참수에서 계산한 camera-ray embedding과 함께 사람별 pose·shape·camera 정보를 복원한다.

| 출력 | 의미 |
|---|---|
| `scores`, `loc` | 사람 신뢰도와 주 keypoint의2D 위치 |
| `rotvec`, `shape`, `expression` | SMPL-X 회전·체형·표정 파라미터 |
| `v3d` | 주센서 카메라 좌표계의 SMPL-X3D mesh, 좌표 단위m |
| `j3d`, `j2d` | SMPL-X layer의3D·2D joint 출력 |
| `transl_pelvis` | 주센서 카메라 좌표계의 pelvis 위치 |
| 평가용55 joints | 공통 joint regressor를 `v3d`에 적용해 계산; pose 지표는 앞22개 body joints 사용 |

body-only는 `_b` 세션 및 body22개 joint 평가 범위를 뜻한다. 출력 layer 자체는 SMPL-X이므로 손·표정 관련 필드가 남아 있지만 이번 실험에서 손·얼굴 정확도를 검증했다고 주장하지 않는다. 모델 입력은 전체 센서 프레임이며 GT 인물 box로 crop하지 않는다.

추론 결과는 먼저 해당 주센서 좌표에서 생성된다. Test에서는 보정값으로 **공통 device3 RGB 카메라 좌표계**로 변환해 동일 GT와 비교한다. 좌표 변환은 예측 후 처리이며 GT 정렬과 구분한다. GT는 추론 완료 후 사람 대응과 지표 계산에만 사용한다.

## 학습과 전체 Test 파이프라인

Train51세션의 고정6,501프레임과 피험자 분리 holdout9세션·288프레임을 사용한다. 고정 subset 한 바퀴를 전체 Train 한 epoch로 부르지 않는다. 실제 본 샘플 수·고유 프레임 수·성공 update와 subset 완료 epoch를 별도로 기록한다. AdamW·AMP·batch16·동일 증강을 유지하고, 첫30분 backbone을 동결한 뒤 마지막8개 block을 작은 학습률로 적응시킨다. 최신 사용자 지시로 융합·event-only의 추가 예산은3시간, RGB-only의 추가 예산은90분이다. 3시간 optimizer 스케줄을90분에 조기 종료하는 방식이며 초기화·검증을 포함한 wall-clock 예산이다. 기존 RGB3의103분 사용자 중단·주기 checkpoint 복구 run은 별도 참고로 보존하고 본 비교에는 새 rgb3_short90 trial을 사용한다. 원본 RGB 두 조건은 ETRI 미세조정0 update로 별도 평가한다. 학습량이 다르므로 관측 차이는 센서만의 효과가 아니다.

주요 학습률은 head1e-5, backbone1e-6, event adapter1e-4, fusion1e-3이다. 학습 손실은 다음과 같다.

```text
L = 100·L_PA + 25·L_pelvis-aligned-body
    + L_detection + L_offset + 0.2·L_rotation + 0.02·L_shape
    + L_absolute-root + 0.01·mean(ΔF²)
```

코드의 `root_weight`가 곱해지는 항은 **pelvis를 맞춘 body pose 오차**다. 주표의 비정렬3D Root position error와 혼동하면 안 된다. 절대 root supervision은 별도의 smooth-L1 항이다. 손실 계산의 좌표는m이고 사용자에게 보이는 pose 오차는mm다.

기존 RGB3/RGB4 Train-selected checkpoint를 해당 RGB 조합과 대조군에 똑같이 불러온다. event-only는 검증된 기존 event-only의 base·projection만 불러오고 이전 fusion은 제외한다. 기존 checkpoint까지의 학습 예산과 새 추가3시간을 구분한다. 원래 사전학습 파일 및 warmstart의 SHA256·split·선택 출처는 실험 manifest에 남긴다.

전체 Test는 body18세션·18피험자의80개10초 구간, 총24,080프레임이다. 원본 RGB 두 조건과 새7학습조건, 총9조건의 동일 공통 GT 표본에서 다음 다섯 열을 산출한다.

| 주표 지표 | 정의 |
|---|---|
| first frame-aligned MPJPE | 정확 frame0에서 구한 pelvis 평행이동을 구간 전체에 고정 |
| first frame-aligned PA-MPJPE | 정확 frame0의 proper Sim(3)를 구간 전체에 고정 |
| frame-aligned MPJPE | 매 프레임 pelvis 평행이동을 다시 구함 |
| frame-aligned PA-MPJPE | 매 프레임 proper Sim(3)를 다시 구함; 반사 금지 |
| Root position error | 비정렬 공통 카메라 좌표에서 `mean(norm(root_pred−root_GT))×1000` |

RPE-Z는 `mean(abs(Z_pred−Z_GT))×1000`으로 따로 보고한다. 미검출을0오차로 채우지 않고 전체 GT 검출률과 공통 표본 크기를 함께 적는다. 원시 예측으로 지표를 재계산하고 cluster bootstrap95% CI·Holm 보정, 동작 속도별 결과, 동일 GPU 순차 속도 및 실제 예측 시각화를 검증해야 최종 완료다.

## 설계 출처와 관련 연구

기존 ViT·patch 검출·HPH·SMPL-X 복원과 내참수 ray embedding은 Multi-HMR의 구성이다. 논문도 카메라 내참수에서 얻은 ray 정보를 token에 반영한다. 이번 수정에서 추가한 것은 센서 간 외부 보정을 사용하는 event 특징 잔차 분기다. [Multi-HMR, ECCV2024](https://www.ecva.net/papers/eccv_2024/papers_ECCV/papers/03364.pdf).

다른 시점의 epipolar 후보 특징을 query와의 유사도·softmax로 결합하는 아이디어에는 기존 연구가 있다. 이번 구현은 RGB/event를 별도 encoder로 처리하고 제한된 Z후보와 residual 초기화를 사용하는 실험용 확장이다. 해당 논문의 공식 구현을 재현했다거나 이 일반 아이디어를 새로 발명했다고 주장하지 않는다. 문헌은 구현 후 설계의 위치를 확인하기 위해 대조했다. [Epipolar Transformers, CVPR2020](https://arxiv.org/html/2005.04551).

가용성 플래그0과 event tensor 자체가0인 경우는 다르다. 현재 모델은 플래그0이면 잔차를 끄지만, 플래그1인0입력에는 큰 잔차를 만들 수 있었다. 중간 checkpoint의 한 Train 프레임 스트레스 검사에서 이를 확인했으며 강건성이 검증된 모델이라고 주장하지 않는다. 자세한 수치와 범위는 실험 보고서의0입력 진단에 기록했다.
