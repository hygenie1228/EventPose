# 학습·평가 경로 연결과 검증



## 재사용 자료와 공정한 출발점 검증

새 source manifest에서 기존 입력 캐시78개(54,101,342,653바이트)의 실제 전체 SHA256, 프레임/timestamp·보정값을 재검증했다. 전체 split의 공동 출연 피험자까지 포함한 Train/Test 피험자 집합이 분리됨을 다시 확인했다. Train6,501행·holdout288행의 cache_row/frame/유효GT/전체센서 가용성 매핑을 전부 대조했다. 각 조건의 Train2·holdout2 샘플, 총20회 실제 입력 비교에서 학습 로더와 평가 로더의 모델 입력 tensor가 정확히 일치했다. event-only의 실제 pixel 접근 집합은 event3,event4뿐이었다.

RGB3와 RGB3+event4는 같은 기존 RGB3 Train-selected checkpoint에서, RGB4와 event3+RGB4는 같은 RGB4 checkpoint에서 출발한다. event-only는 기존 event-only checkpoint의 base와 polarity projection을 검증해 가져오되 이전 fusion은 가져오지 않는다. 세 원본 checkpoint를 실제 CPU 로드해 split·선택단계·평가 step·유한 가중치·파일 해시를 검사했다. 신규 trial의 추가3시간은 출처 checkpoint의 기존3시간 학습과 별개이며 누적 학습 출처와 표본 수를 구분 보고한다. 기존3시간 결과를 새6시간 대조군과 동등한 예산 결과로 주장하지 않는다.

기존 head/backbone LR은1e-5/1e-6, 새 fusion LR은1e-3, event adapter LR은1e-4로 분리했다. 첫30분 backbone 동결과 AdamW/AMP·동일 batch16·동일 증강·동일 subset을 유지한다. 새 event-only에는 기존1×1 polarity projection을 보존하는 공간 refiner를 추가했다. event CNN의 stride8 특징 좌표와 원본 event 픽셀 좌표 간 변환도 명시적으로 반영했다. 새 학습의 gradient와 residual 규제를 기록해 보조 분기가 실제 학습되는지 확인한다.

## 실제 모델의 CPU 초기화 검증

세 조건 모두 실제 사전학습 Multi-HMR와 검증된 출처 checkpoint를 로드하고 동결된 실제 Train 프레임으로 native 추론했다. 각 조건에서 원래4096×1024 backbone 특징을 CPU에서 실제 추출하고, 동일 특징으로 event 가용/미사용 추론을 비교했다. zero residual 초기화에서 모든 예측 mesh가 정확히 같음을 검사했다. 실제 추론 입력에 GT를 넣지 않았고 event-only의 RGB 입력은 없다. 추론 결과는 `diagnostics/`에 저장했다. 이 검사는 한 Train 프레임의 초기 추론 검사이며 전체 Test, 학습 후 개선, GPU 속도 측정을 대체하지 않는다. 근거: `source_reuse_audit.json`, `real_data_cpu_preflight.json`, `native_cpu_preflight.json`, `warmstart_manifest.json`.

실행 관리기와30분 보고서 갱신기를 등록했다. 현재 CUDA 가능 GPU가 없어 본학습/전체Test는 모두 미평가다. GPU 복구가 확인되면8-update 실제 GPU pilot5조건을 먼저 검사하고, RGB 초기 검출 지표 일치와 event encoder gradient를 통과한 뒤 서로 독립적인 본학습5조건을 실행한다. pilot 가중치는 본학습에 사용하지 않는다.

새 scheduler PID35922, report PID35923, deadline watchdog PID22348이 실제 살아 있음을 확인했다. CUDA probe는30분 간격으로 재시도한다. GPU1/2/4/5 외의 장치를 실행하지 않는다. 새 방법의 최종 성능 개선은 아직 미평가다.
