# Event-only 진단의 검출 폭증 자원 실패와 복구

한국시간2026-10-27 23:22 점검에서 전체9조건 Test가 끝났음을 확인했다. 후속 event3_event4 holdout 진단은 intact284/288, missing285/288 처리 후 zero_aux 모드에서684.89GiB 할당 요청으로 종료했다. 실패 로그를 보존했다. 정상 Test나 checkpoint의 오류가 아니라 인위적0 입력의 검출 후보 폭증으로 native HPH의 후보별 KV 확장이 메모리를 초과한 것이다.

진단에만 프레임당16개 초과 후보가 있으면 해당 프레임 전체를 자원실패로 기록하고 무거운 복원 전에 제외하는 보호를 넣었다. 상위16개로 바꾸는 방식이 아니며, 다른 프레임의 후보와 score는 그대로다. CPU 합성 검사에서 정상 후보의 동일성과 폭증 프레임 전체 제외, 다른 프레임 보존을 확인했다. 전체GT 분모에 자원실패도 남기고 실패GT 수를 별도 표시하며 공통 검출 표본이 없으면 오차는 미평가다. 보호된 프레임을 native 검출률·pose 오차 평가 완료로 주장하지 않는다.

본학습·정상 Test의 입력·검출 threshold·모델·가중치와 동결 source8파일은 변경하지 않았다. 기존에 완료한 두 RGB 융합 진단 결과는 보존했다. 실패한 진단의 원인을 확인하고 보호를 검증한 뒤 후속 관리자만 재실행했다. 이후 원시진단·동일GPU 속도·통계·전체 보고서 감사가 필요하며 Goal은 계속 active다.
