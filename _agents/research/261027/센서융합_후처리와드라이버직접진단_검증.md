# 후처리 연결과 직접 드라이버 진단



## 원본 자료 재대조와 실행 전 검증 보강

실제 현재 마운트된 dataset의78개 세션에서 고정 자료와 시계·내외부 보정·RGB 영상 메타데이터·캐시 대상 GT pose/betas/translation을 전부 대조해 일치를 확인했다. 원본 RGB/event archive 전체 bytes를 다시 해시한 것은 아니며, 전체 캐시 bytes 해시와 원본 수정시각·메타데이터 대조를 구분한다. 별도로 새 경로에서 SMPL-X GT54개를 독립 CPU 재구성해 최대 차이1.430511474609375e-6 m를 확인했고, 재사용 GT158파일의 해시를 고정했다. body 학습51명·holdout9명·Test18명은 세션명의 모든 피험자 토큰 기준으로 분리됨을 확인했다.

새 ablation 진단 도구도 실제 full Multi-HMR·검증된 RGB4 초기화와 실제 holdout1프레임으로 CPU 실행했다. 네 입력 변경 방식이 초기 zero residual 상태에서 같은 예측을 내고 정상 매칭됨을 확인했다. 이는 도구 동작검사이며288프레임 내부 검증이나 새 Test 성능으로 사용하지 않는다. 원본 사전학습 파일 SHA256은 `c1b55933eb35df9b27966e1d8d3a69c4bc5e28eee0f0dd7f0cdc41c3f27202ca`로 고정했다. 실제 실행 때 모델·데이터·학습·평가 코드 해시와 원문 text snapshot을 함께 보존하도록 했다.

## 드라이버 직접 진단

GPU1 UUID를 지정한 독립 프로세스에서 PyTorch를 통하지 않고 CUDA driver API `cuInit(0)`을 호출했지만 오류3 `CUDA_ERROR_NOT_INITIALIZED`로 실패했다. 로드한 libcuda와 커널 드라이버 버전은 모두545.29.06이었다. 모델 실행과 장치 context 생성 전 초기화 단계의 실패이므로 모델 수정만으로 현재 새 GPU 작업을 시작할 수 없다. 장치 reset·재부팅·타인 작업 종료는 하지 않았다. 세부 증거는 `direct_cuda_driver_diagnostic.json`에 남겼다.

후처리 관리기는 실제 본학습5조건과 전체Test 완료 후에만 full holdout ablation, 동일GPU10회 속도 측정, 원시지표/전체체크포인트/코드/보고서숫자 감사를 실행한다. 최종 감사가 통과하더라도 agent의 실제 그림·결과·한계 검토 전에는 Goal complete를 자동 선언하지 않는다. 현재 새 본학습·전체Test는 여전히 미실행이다.

실제 CPU 진단 파일: ablation_cpu_preflight.json, current_dataset_audit.json, actual_input_audit.json, reused_groundtruth_hashes.json, body_holdout_subject_audit.json. 보고서 parser가 실제 과거 집계의 정상 값과 CI를 수락하고1mm 변조 값을 거부함을 검사했다. 새 전체Test 미완료 상태에서 최종 감사가 차단됨을 실제 호출로 확인했다.
