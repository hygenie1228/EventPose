# 부위별 운동 감독 라벨 추가

2026-10-29 한국시간. V1/V2 모델과 실험은 수정하지 않았다. V3의 별도 보조 운동 예측기를 검토하기 위해 기존 CPU GT 생성 helper에 역할 선택을 추가했다.

명령은 `tools/prepare_part_aggregation_motion_diagnostics.py --role training` 또는 `--role validation`이다. 각각 고정 Train6501질의와 Train 내 validation288질의를 사용하며 Test는 포함하지 않는다. 출력은 기존 holdout 진단과 다른 `diagnostics/training_part_motion_targets.npz` 및 `diagnostics/validation_part_motion_training_targets.npz`이다. 기존 holdout NPZ/JSON은 SHA를 보존 검증하고 덮어쓰지 않는다.

부위별 `event3_part_path_px`는 native event3 카메라의200ms 경로 길이다. 새 `event3_part_displacement_uv_px`는 각 부위 관절의 end−start signed(x,y) 변위를 평균한 값으로 방향을 보존한다. 두 값은 서로 다르며 왕복 운동은 경로 길이가 커도 순변위가 작을 수 있다. `sessions`·`frames`로 입력 표본을 연결하며 `subject_id`와 `part_names`도 보존한다.

`valid`와 `part_valid`는 과거GT 시간 범위와 정상 깊이에 따른 감독 마스크다. 가시성 비율은 별도 필드에 있어 필요하면 추가로 마스킹할 수 있다. 30Hz GT의 시작점 선형 보간, 끝점 최신 과거GT 유지, RGB와 common GT 시계 차이는 기존 진단과 동일하다. 미래 GT로 부족한 초기 구간을 메우지 않는다.

Train 파일만 `training_supervision_allowed=True`이며 validation 파일은 optimizer 감독에 사용할 수 없다. 모든 파일의 `inference_input_allowed=False`다. GT 운동 라벨을 추론 입력으로 전달해서는 안 된다. 모델의 시간 선택이 동적으로 개선되는지는 보조 운동 정확도와 별개로 검증해야 한다.

CPU 프로세스13403·13404는 전용 managed_jobs에 등록했고 고정 마감1793321712를 적용했다. CUDA를 비웠으며 GPU, 모델 코드 및 장기 학습의 진행 상태를 조회하거나 변경하지 않았다. 최종 검증은 출력 파일의 시계·벡터·고유 표본 키와 원본 라벨·기존 holdout SHA 보존을 대상으로 한다.
