# V6 보조손실 분리 후속 검토

기록: 2026-10-30 01:14 KST, 단일 담당 /root. **연구 초안이며 실행 승인·설정 동결·GPU 등록을 하지 않았다.** 현재 V6 네 학습은 보존한다.

## 질문과 현재 근거

01:11 정기검토에서 V6 fixed/global Train holdout PA는24.748436/24.751710mm, part는24.765590mm였다. 강한 RGB24.753125mm 대비 부위 동적 집계의 개선은 아직 없다. 이는 진행 중인 학습의 일부 결과이므로 실패 확정이나 후속 실행 승인의 충분한 근거로 삼지 않는다. V6 완료 Train checkpoint의 intact/zero/missing/shuffle 진단을 먼저 기다린다. V6 전체Test는 후속 방법 선택에 사용하지 않는다.

## 분리 가능한 단일 요인

V6 architecture·동일 frozen RGB/V3 초기화·이벤트 인코딩·보정·세 구간·32격자·학습률·seed·batch8·warmup500·최대3000업데이트/3시간을 모두 유지하고, motion_aux_weight만0으로 바꾸는 fixed/global/part/static 네 대조군을 고려한다. 이는 의미 특징을 교체한 V6에서 보조손실의 영향을 분리하며 V3 no-aux 결과와 직접 대체 관계가 아니다. 보조손실이0이어도 추론 때 motion head와 horizon은 그대로 사용하고 자세손실을 통해 학습한다. 감독에 쓰인 GT motion은 여전히 추론 입력이 아니다.

## 실행 전 확인

- 완료 Train 진단의 actual bytes SHA와 holdout 오차로만 필요성을 판단한다. 지금은 진단을 추가 조회하거나 GPU를 실행하지 않는다.
- 실제 필요성이 확인되면 새 이름의 설정만 만들고 main/pilot 각4개를 사전 동결한다. 기존 V6 설정과 소스는 수정하지 않는다.
- no-aux fixed에서는 motion head의 gradient가0인 것이 구조상 정상이다. 기존 pilot gate의 무조건 motion_head>0 요구를 그대로 재사용하면 안 된다. event encoder의 실제 pose gradient, 동적 조건의 time/event-use gradient, frozen base 불변·전체 checkpoint 재로딩을 각 조건에 맞게 검증한다. 동적 horizon이 포화되어 pose gradient가 전혀 없으면 그 사실을 숨기지 않는다.
- 기존 관리기 등록·전용 pilot·동결/승인·신원 보존 교체 절차로만 편입한다. 중복 관리기·agent·학습을 만들지 않는다.
- 기존 V3/V2 후속 대조군을 삭제하지 않는다. 실행 예산과 고정09:55:12KST 마감에 맞지 않으면 미실행을 기록한다.

이 초안은 no-aux의 개선을 예측하거나 보장하지 않으며 현재 Goal/hash·마감·동결모델을 바꾸지 않는다.
