# 부위별 동적 집계 평가 구현 메모

작성일: 2026-10-29 한국시간. 이 메모는 새 모델의 성능 결과가 아니다.

## 재사용 프로토콜

기존 `exp/261028/device3_encoding_12h`의 body 전용 분할은 학습 51세션·6,501선택 프레임, 학습 내부 holdout 9세션·288프레임, Test 18세션·80개의 약10초 구간·24,080프레임이다. 전체 데이터셋의 219/64세션과 혼동하면 안 된다. 같은 장치 번호의 RGB와 이벤트도 별도 카메라이므로 보정된 K/R/t를 사용한다. 기존 공통 시각은 device0 corrected RGB 시각이고, 선택된 실제 RGB3 시각은 그보다 최대 50ms 과거일 수 있다. 새 memory는 실제 RGB3 시각까지만 사용한다.

## 새 평가 API

`src/multihmr/part_aggregation_evaluation.py`의 `evaluate(config, rank=0, workers=1)`는 학습 내부 holdout으로 선택한 best checkpoint를 동결하고, 같은 device3 RGB+event3를 이용해 세션 shard를 추론한다. 모델 입력은 `model.input_keys`만 통과한다. GT는 추론 후 네이티브 RGB 카메라의 2D 대응으로 평가 사람을 매칭할 때만 사용한다. 검사 중 checkpoint hash를 고정하고, 마감에서 부분 결과를 보존한다.

`analyze(config, names)`는 모든 Test 구간을 완료한 조건만 대상으로 한다. 완료 조건 전체 공통 표본, RGB 기준 각 방법의 쌍별 공통 표본, 조건 자체 표본을 별도 저장한다. 18피험자 단위 bootstrap/sign-flip와 family별 Holm 보정을 계산한다. Test 결과는 방법/가중치 선택에 사용하지 않는다.

`src/utils/part_aggregation_metrics.py`의 `score_chunk`와 `summarize_chunks`는 22관절의 4개 자세 지표와 RPE-Z를 계산한다. 정확한 chunk frame0에서 공통 검출이 없는 사람은 제외하며 이후 첫 검출로 대체하지 않는다. 첫 프레임의 pelvis translation 또는 proper Sim(3)는 구간 전체에 고정된다. RPE-Z는 정렬 전 pelvis의 Z축 절대오차이며 3차원 root norm과 다르다. 원시 합은 m, 표시는 mm다.

## 검증

8개 CPU 단위 검증과 기존 실제 예측 3개 chunk·903표본에서 기존 검증된 `segment_metrics`와 5지표를 대조했다. 원시 합과 최종 mm 평균이 수치 오차 이내에서 일치했다. 이것은 기존 예측에 대한 평가 구현 검증이며 새 방법 결과가 아니다. 추가로 네 조건 전체/부분 완료의 합성 CPU 집계 검증을 수행했다. 합성 검증 자산은 `exp/261029/part_aware_dynamic_aggregation/evaluation_cpu_check`에 격리되어 있으며 보고서 실제 결과에 섞지 않는다.

평가 교란은 `zero_event`(관측값만0), `missing_event`(관측값·available 모두0), `shuffle_event`(batch내 순환), `reverse_time`(시간bin내용 순서반전)를 제공한다. batch크기1에서는 shuffle이 바뀌지 않으므로 해당 개입의 한계가 있다.

실제 새 모델의 CUDA 추론은 전담 학습 agent가 수행할 pilot/본평가에서 확인해야 한다. 데이터셋·data 원본은 수정하지 않았고 GPU job은 실행하지 않았다.
