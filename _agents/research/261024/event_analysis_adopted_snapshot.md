## 지금까지 확인한 사실

현재 `dataset/`의 이벤트에는 시간 오프셋 보정이 적용되어 있다. 같은 프레임 번호끼리 연결하지 않고, 이벤트와 RGB의 보정된 타임스탬프로 연결해야 한다. 이벤트는 자체 카메라의 960×720 좌표에 있으며, RGB 영상과 픽셀 단위 공간 정렬을 적용한 상태는 아니다.

저장된 이벤트 프레임의 확인된 값은 `−128`과 `+127`이다. 이번 비교에서는 부호만 사용해 극성을 같은 가중치로 계산했다. 누적 횟수는 저장된 프레임에서의 활성 관측 횟수이며, 원시 이벤트의 정확한 발생 횟수나 프레임 안의 개별 시각을 복원한 값은 아니다.

원본 데이터셋은 읽기만 했다. 분석 출력은 `exp/261024/event_encoding_comparison/`에 저장했다. 계산과 인코딩은 CPU로 수행했으며 기존 GPU 작업을 조작하지 않았다.

## 비교한 설정과 주요 관찰

| 설정 | 관찰 |
| --- | --- |
| 부호 합산 후 이진 표시 33ms | 이동 경계는 보이지만 양·음 극성이 같은 픽셀에서 상쇄될 수 있음 |
| 극성 분리 누적 33ms | 빠르게 움직이는 팔의 현재 윤곽이 비교적 선명함 |
| 극성 분리 누적 100ms | 윤곽이 조밀해지는 대신 이동 흔적이 늘어남 |
| 극성 분리 누적 200ms | 팔 동작의 과거 위치가 넓게 남아 현재 자세를 읽기 어려움 |
| 시간 표면 50ms | 오래된 흔적을 약화하지만 빠른 동작에는 잔상이 남음 |
| 시간 구간 세 개로 나눈 100ms | 이동 순서를 색으로 구분할 수 있음 |
| 고립 점을 줄인 100ms 누적 | 배경 점은 줄지만 긴 누적의 잔상은 남음 |
| 여러 누적 길이 33ms 및 100ms 및 200ms | 짧은 관측과 오래된 관측을 함께 표시하지만 현재 실루엣 하나로 해석하면 안 됨 |
| 시간 표면 20ms | 최근 팔 위치를 더 강조하며 작은 움직임이나 정지 부위는 어두워짐 |
| 고립 점을 줄인 33ms 누적 | 현재 윤곽과 배경 점 감소를 함께 확인할 수 있어 시각화 기본값으로 추천 |

전신 영상 12초 부근의 팔 내리기에서 차이가 뚜렷하다. 200ms 누적은 이전 팔 위치가 부채꼴로 남는다. 33ms 누적은 흔적의 범위가 작으며, 시간 구간 표현은 이동 경로의 순서를 보여 준다. 한편 얼굴과 상체의 작은 움직임에는 짧은 누적만으로 신호가 부족할 수 있다.

## 현재 추천안

확인용 영상에는 **33ms 극성 분리 누적과 약한 고립 점 제거**를 기본값으로 사용하고, **시간 표면 20ms**와 **100ms의 시간 구간 표현**을 나란히 본다. 윤곽과 이동 순서를 한 가지 누적 영상에 모두 담으려 하지 않는 방식이다.

자세 추정 학습의 작은 기준선으로는 **세 시간 구간과 양·음 극성을 분리한 6채널 입력**을 제안한다. 다음 비교 후보는 100ms를 다섯 시간 구간으로 나눈 극성별 10채널, 극성별 시간 표면 2채널, 200ms 누적 2채널을 합친 14채널이다. 긴 구간은 짧은 구간에 직접 합치지 않고 보조 채널로 둔다.

이 학습 후보는 영상 관찰에서 도출한 제안이다. 모델을 학습하거나 자세 추정 오차로 순위를 검증한 결과는 아니다. 이벤트가 발생하지 않는 정지 부위까지 인코딩만으로 항상 완전한 윤곽을 복원할 수 있다고 가정하지 않는다.

## 기존 시각화 도구 방식과의 추가 비교

### 원래 도구의 실제 처리

[기존 도구의 희소 이벤트 변환 함수](/home/namhj/EventPose/tools/visualize_data.py:181)는 저장된 각 이벤트 프레임을 하나씩 복원한다. 배경을 회색 128로 채우고, 해당 프레임의 양극성 픽셀을 흰색 255, 음극성 픽셀을 검정 0으로 표시한다. 다른 프레임과의 누적, 발생 빈도의 밝기 표현, 시간 감쇠, 고립 점 제거는 없다. 이 동작 자체는 저장된 프레임을 확인하기 위한 단순하고 명확한 표현이다.

기본 영상 변환은 모든 이벤트 프레임을 **고정 250fps**로 기록한다. 이벤트 타임스탬프를 읽어 재생 간격을 결정하지 않는다. 기본 작은 해상도 설정은 480×360과 압축 품질 CRF 28이다. 이미지 추출 모드는 RGB 프레임 번호의 50배로 이벤트 프레임을 선택하므로, 현재 데이터에서 정확한 시점 대응에 사용할 수는 없다.

- [흑백 33ms 누적을 추가한 전신 원해상도 영상](/home/namhj/EventPose/exp/261025/event_encoding_visualize_data/body/gray_signed_33ms.mp4)

비교판은 위쪽에 RGB, 기존 도구의 단일 프레임 흑백 표현, 흑백 33ms 누적을 배치했다. 아래쪽은 기존 추천 설정인 주변 지지점을 확인한 극성 분리 누적, 시간 표면, 세 시간 구간의 모션 표현이다. 전신은 33ms 윤곽 및 시간 표면 20ms와 비교했고, 얼굴은 기존에 생성한 100ms 윤곽 및 시간 표면 50ms와 비교했다. 얼굴의 시간 표면 패널은 기존 비교판의 해당 패널을 재사용했으므로 표시 해상도가 축소된 상태다.

원래 함수를 변경하지 않고 직접 호출했다. 다만 공정한 시간 비교를 위해 각 RGB 시점 이하의 가장 최근 이벤트 프레임을 골라 600행의 임시 희소 행렬을 만들고, 그 행들을 10fps 및 960×720 및 CRF 18로 렌더링했다. 따라서 **단일 프레임의 복원 규칙은 원래 함수 그대로이며, 프레임 선택과 출력 속도 및 압축 조건은 비교를 위해 조정했다.** 기본 실행의 250fps 영상 전체를 그대로 재현한 것은 아니다.

현재 데이터의 실제 앞 60초에서 고정 250fps와 타임스탬프의 차이는 다음과 같다.

| 샘플 | RGB 시작부터 60초 안의 이벤트 프레임 수 | 이 프레임들을 전부 250fps로 기록했을 때 길이 |
| --- | ---: | ---: |
| 전신 동작 | 59,504 | 238.016초 |
| 얼굴과 상체 | 59,160 | 236.640초 |

이 수치는 관측된 프레임 수를 250으로 나눈 계산이다. 원래 도구의 이벤트 출력에서 비디오 시각 60초를 실제 RGB 촬영 60초로 해석하면 안 된다. 이번 비교판은 보정된 타임스탬프를 이용해 같은 촬영 시점에 맞췄으며, 영상 길이는 모두 60초다.

### 윤곽과 모션에서 관찰한 차이

![기존 시각화 도구와 다른 표현의 전신 12초 비교](/home/namhj/EventPose/exp/261025/event_encoding_visualize_data/body/comparison_12s.jpg)

전신 12초의 원래 단일 프레임 표현에서는 팔과 손의 일부 신호가 주로 보이며, 머리와 몸통을 이어 읽기 어렵다. 같은 시점의 흑백 33ms 누적에는 머리와 몸통 윤곽이 나타난다. 극성 분리 누적과 시간 표면에서도 인체 구조를 더 연속적으로 볼 수 있다. 따라서 이 장면의 핵심 차이는 흑백과 컬러의 선택보다 **한 장의 저장 프레임만 쓰는지, 짧은 시간의 여러 프레임을 통합하는지**에 있다.

| 표현 | 윤곽과 모션에 대한 판단 |
| --- | --- |
| 기존 도구의 단일 프레임 흑백 복원 | 원본 관측 확인에 적절하다. 각 순간의 입력이 희소해, 한 장만으로 안정적인 전체 자세를 읽기에는 정보가 부족한 장면이 있다. |
| 흑백 33ms 누적 추가 버전 | 흑백이어도 윤곽이 훨씬 연속적으로 보인다. 다만 양·음 누적을 하나의 부호로 합쳐 극성이 상쇄되고, 시간 순서와 빈도 정보를 잃는다. |
| 극성 분리 33ms 누적 | 현재 윤곽을 짧은 구간으로 모으면서 양·음 정보를 따로 유지한다. 약한 이웃 필터를 병행한 시각화 추천을 유지한다. |
| 시간 표면 | 최근 움직임을 강조해 현재 위치와 오래된 흔적을 구분하는 데 도움이 된다. 정지 부위가 약해지는 성질은 남는다. |
| 시간 구간별 모션 표현 | 이동 순서를 표현한다. 학습 입력은 표시용 색으로 합치지 않고 극성별 수치 채널을 유지하는 쪽을 제안한다. |

새로 추가한 흑백 33ms 버전은 원래 도구의 기능이 아니다. 극성별 관측 횟수를 같은 가중치로 센 후 차이의 부호가 양이면 255, 음이면 0, 동률이면 배경 128로 표시한 비교용 확장이다.

희소성은 원해상도에서 활성 픽셀 수로도 확인했다. 이벤트 시작 후 최소 33ms의 관측이 확보된 비교 시점에서 구한 중앙값이다.

| 샘플 | 원래 단일 프레임의 활성 픽셀 수 | 33ms 구간에서 한 번 이상 활성인 픽셀 수 | 흑백 부호 합산에서 양·음 동률로 사라진 픽셀 수 |
| --- | ---: | ---: | ---: |
| 전신 동작 | 1,939 | 31,488.5 | 2,401.5 |
| 얼굴과 상체 | 545 | 11,478 | 1,019 |

전체 691,200픽셀 중 단일 프레임의 활성 비율은 전신에서 중앙값 약 0.281%, 얼굴에서 약 0.079%다. 33ms 구간의 활성 픽셀 합집합은 각각 약 4.556%와 1.661%다. 합집합에는 배경 잡음도 포함되므로, 이 숫자가 크다는 사실만으로 사람 윤곽 정확도나 자세 추정 성능이 좋다고 판정하지 않는다. 표의 각 열은 시점별 값을 따로 중앙값 낸 결과이며, 열끼리 빼서 최종 활성 픽셀 수를 구하면 안 된다.

단일 프레임 영상은 원래 고빈도 스트림 전체를 10Hz로 압축해 관찰한 비교다. 고빈도 프레임 전체를 순차 처리하는 별도의 시간 모델의 성능을 평가한 것은 아니다. 이번 결과는 원래 저장 프레임을 한 장의 자세 입력으로 사용할 때의 희소성과, 짧은 시간 통합의 효과를 보여 준다.

### 추가 비교 후 추천

흑백 표현 자체를 배제할 이유는 없다. 다만 사람의 윤곽과 자세 변화를 위한 학습 입력으로는 기존 도구의 단일 프레임 복원 영상을 그대로 쓰기보다, **33ms 극성 분리 누적, 시간 구간별 극성 분리, 시간 표면을 각각 비교**하는 방향을 유지한다. 원래 단일 프레임 흑백 표현은 원본 확인용 기준으로 함께 보존한다.

추가 비교 코드는 [기존 시각화 방식 비교 도구](/home/namhj/EventPose/tools/compare_visualize_data.py)에 있으며, `.venv-humanpose/bin/python tools/compare_visualize_data.py`로 실행한다. 두 출력 폴더의 `settings.json`에는 원래 도구의 소스 해시, 선택한 이벤트 및 RGB 프레임 번호, 시간 조건과 픽셀 통계를 기록했다. 추가 작업에서도 원본 시각화 도구와 데이터셋을 변경하지 않았다.
