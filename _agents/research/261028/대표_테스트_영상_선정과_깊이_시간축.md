# 대표 테스트 영상 선정과 깊이 시간축

사용자 요청으로 새 Native Goal을 만들었다. 완료된9조건을 동일5구간에서 시각화하고 기존 센서융합 재실험 보고서에45개 MP4 링크를 추가한다. 정량 메인표는 맨 앞에 유지한다. 새 출력은 exp/261028/device34_test_video_gallery, 임시 reference는 /mnt/disk5/EventPose/261028/device34_test_video_gallery다. 기존 데이터와 가중치는 읽기전용이다.

전체 Test80구간의 GT body22 관절 속도 중앙값 분포에서10/30/50/70/90분위에 가까운 구간을 서로 다른 피험자로 선택했다. 피험자는110,234,255,256,106이며 모델 오차를 선정에 쓰지 않았다. 5구간과 checkpoint9개 SHA는 manifest.json에 동결했다. 새 추론은 해당5구간만 수행하고 모든 검출 mesh를 저장한다. GT box/crop이나 pose 정렬을 영상 생성에 사용하지 않는다. 기존 정량 Test의 matched prediction joints와 새 mesh의 regressed joints를 대조한다. RGB/event/depth 참고 화면은 CPU 렌더러에서만 읽으며 event-only 모델 추론은 event3/event4 픽셀만 읽는다.

각 MP4는 RGB3, RGB4, 두 event count33, mesh만의 고정3D시점, 공통RGB3 카메라 overlay, depth scene의6패널이다. 입력 sensor를 상단에 명시하고 RGB 참고 패널을 구분한다. Event 표시는 모든 최종본에서 gain4로 통일한다. 초기 표시 설정과 depth 위치 대응을 점검하기 전 제작본은 initial_render_v1에 보존했으며, 최종본은 render_version2로 분리하고 기존 mesh는 재추론하지 않았다. CPU z-buffer의 근거리/원거리 면 및 실제 배경 depth 가림을 합성 기하로 검사했다.

Depth가 있는 구간은 clip01,clip02,clip05다. clip03/04는 device0~4 어디에도 depth.mp4가 없음을 확인했다. 보관 depth는 lossless H264 RGB에 uint16값을 R=하위byte,G=상위byte,B=0으로 저장한5Hz 부분집합이다. 라벨 source_depth_position은30Hz 원본 위치여서 MP4 위치와 다르다. 처음에는 위치를 같다고 보는 보수적 검사 때문에 배경을 만들지 않았으나, 실제 timestamp로 비교하니 보관 영상의 모든 timestamp가 원본30Hz timestamp 집합에 정확히 포함됨을 확인했다. frame index에 상수를 곱해 시간을 추정하지 않는다. 클립 첫 시각보다 늦지 않은 최근 depth만 사용한다.

정합에는 depth의4K RGB-aligned pixel plane과 rgb_calibration__rgb__pre_resize_intrinsic_matrix를 사용한다. resize transform과 모델 native K의 일치 및 backprojection/reprojection을 확인한다. Scene은 첫 과거 depth의 정적 부분 관측이며, RGB3 단독 예측 범위로 사람 부분을 제거한다. 모델이나 GT에 맞추어 scene을 변환·최적화하지 않는다. 빈 영역은 채우거나 생성하지 않는다. 원본 unit tag가 source_raw_unit이므로 제공 예제의0.001m/unit을 사용한다는 가정을 영상과 보고서에 명시하며 독립 센서 단위 인증으로 표현하지 않는다.

완료 조건은45개 최종 MP4 전체 디코딩·301프레임/fps/1920x864·입력/mesh/source timestamp 대조·실제 contact 프레임 수동 확인·보고서45링크와 기존154행 정량값 유지 검증이다. 파일 존재나 첫 제작본만으로 Goal을 완료하지 않는다.
