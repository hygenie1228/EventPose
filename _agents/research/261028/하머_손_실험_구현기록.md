# HaMeR 손 실험 구현 기록

- 사용자 지정: `_h` 손 데이터, 공식 HaMeR pretrained, 기존 body 컨벤션 적용. 추가 지정으로 GPU0에서 RGB3 및 RGB3+Event4 세 인코딩의 총 네 학습 조건만 실행한다.
- 사용자가 GT 손 박스 crop 복원 평가를 선택했다. 손 검출을 평가하지 않으며 GT 좌우 손 박스 사용을 보고서에서 명시한다.
- RPE와 RPE-Z는 계산하지 않는다. wrist를 root로 네 가지 정렬 MPJPE/PA-MPJPE만 보고한다. 학습의 wrist 평행이동 감독은 첫 프레임 고정 정렬의 시간 변화 복원을 위해 유지한다.
- 원본 split에서 `_b` Train60/Test18, `_h` Train63/Test18. 기존 body 검증 피험자 IDs와 동일하게 hand 학습54/검증9/Test18로 분리했다.
- 공식 저장소 commit 및 원본 파일 체크섬은 `hamer_upstream.json`에 기록했다. 코드와 라이선스는 `src/hamer/`에 포함했다. upstream 선택적 import만 가볍게 바꾸고 ViT-H 및 MANO head 구현은 유지했다.
- dataset/data는 읽기 전용이다. 이번 다운로드는 실험의 assets에 저장한다. 기존 MANO_RIGHT.pkl을 재사용한다.
- 실제 crop 그림 검사에서 source GT 박스가 3840×2160이고 처리된 RGB가 1280×720인 불일치를 발견했다. 원본 source intrinsic/distortion에서 rectified RGB intrinsic으로 박스 경계를 변환하도록 수정했다. 잘못된 최초 캐시는 실험 tmp/crop_diagnosis_v1에 보존하고 cache_version2만 허용한다.
- HDF5 NFS 파일 잠금은 진단 읽기에서 대기 상태를 유발했다. 실험 데이터는 모든 경로에서 읽기 전용 locking=False로 열고 source를 변경하지 않는다.
- 모델에 GT 관절은 전달하지 않는다. 허용된 GT crop 변환·박스·좌우성, 관측 이미지, 센서 calibration만 입력한다. Test는 checkpoint 선택에 사용하지 않는다.
- Persistent Goal은 생성하지 않는다. 학습·평가는 30분 간격으로 확인하며 본인 PID/PGID/시작 tick을 기록한다.
- 수정된 실제 손 crop을 육안 확인했고, 검증 손 표본8개의 21관절은 모두 crop 내부에 있었다. 네 지표의 항등·반사금지·원래 frame0 누락 처리, 이벤트 인코딩의 인과 시각 검사를 통과했다.
- 실제 Event4 관측·calibration을 사용한 세 인코딩의 융합 검사를 통과했다. 초기 잔차0에서 RGB 특징을 정확히 보존하고, 1회 출력층 갱신 뒤 이벤트 CNN에 양의 gradient가 전달되며, 보조 센서 unavailable일 때 RGB 특징이 보존됨을 확인했다.
- GPU0은 UUID `GPU-53cb4ca2-0dad-f82c-9056-589efd4d509d`, Quadro RTX8000이며 실제 CUDA matmul을 통과했다. 다른 GPU의 작업을 중단하거나 재시작하지 않았다.
- 학습 및 평가 진입점은 tools를 import하지 않는다. 전체 Test·네 학습·원시 예측·그림·공통 표본·checkpoint 확인 후에만 자동 실행 상태를 complete로 표시한다.
- 공식 archive SHA256 `ccfb70abd672b64c3ea90891c808d4499cc36a37dd6cf86c561a665113aef11e`, HaMeR checkpoint SHA256 `e5cc06f294d88a92dee24e603480aab04de532b49f0e08200804ee7d90e16f53`을 실제 파일에서 계산했다.
- GPU0에서 원본 및 세 융합의 pretrained 전체 forward를 통과했고, 초기 융합 결과와 원본 RGB의 최대 관절 차이는 세 조건 모두 정확히0m였다. 근거는 실험 `gpu_preflight.json`이다.
- RGB 짧은 학습 검증은8회 모두 optimizer 갱신 성공,64개 고유 Train 손 표본·128개 표본 처리, 실제 best/last checkpoint 저장까지 확인했다. 이 가중치를 본학습 초기화로 재사용하지 않는다.
- NFS lock-manager 대기로 첫 학습 진입이 지연되어 본인 scheduler와 아직 업데이트 전이던 첫 pilot만 종료 후 로컬 lock으로 수정했다. 본학습은 시작 전이었다. 이후 RGB 검증이 통과했다.
- 본학습 네 조건의 checkpoint는 `.experiment_storage/hamer_hand_261028/checkpoints/` SSD backing에 저장하고 `exp/261028/hamer_hand/checkpoints/{조건}/` symlink로 접근한다. 현재 실행 중이던 pilot의 기존 저장 경로는 보존했다. SSD backing은 활성 실험 동안 삭제하지 않는다.
- 네 조건 모두8/8회 실제 optimizer 갱신과 checkpoint 저장을 마쳤고, 세 융합 모두 실제 Train 입력의 이벤트 encoder gradient가 양수임을 확인했다. GPU0에서 RGB90분 본학습을 시작했으며 이후 세 융합 각3시간 및 전체 Test를 순차 실행한다. 이 시점은 실험 완료가 아니며 Test 실측값은 아직 없다. 실제 증거는 실험 `implementation_handoff.json`, `pilot_checks/`, `gpu_preflight.json`, `checkpoint_roundtrip_preflight.json`이다.
