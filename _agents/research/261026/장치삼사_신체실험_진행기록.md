# 장치 3·4 신체 실험 진행 기록

사용자가 이전 10조건 실험을 취소하고 6조건의 body 비교로 Goal을 교체했다. 이전 등록 작업의 정지를 확인했고 결과는 보존했다. 새 Goal은 활성 상태이며 고정 마감은 2026-10-27 12:33:29 UTC다.

주표는 정확 frame0 고정 및 매 프레임 pelvis/Sim3 정렬 4지표와 비정렬 3차원 Root position error의 다섯 수치열이다. RPE-Z는 별도 보조 지표다. 기존 지침의 RPE-Z 주표 문구보다 이 사용자의 최신 6조건 요청을 따른다.

원본 Multi-HMR의 실제 GPU 합성 입력 사전 실행에서 여섯 모델 모두 유한 출력을 확인했다. 이는 실제 데이터의 학습·Test 결과가 아니다. CPU 데이터 검사에서는 비항등 센서 좌표변환 왕복·센서 간 상대변환·GT 필드 추론입력 배제·이벤트 두 센서 조건의 RGB 픽셀 무접근·동일 표본 수를 확인했다. 독립 SciPy proper rotation 구현과 기존 집계 구현의 다섯 지표가 합성 데이터에서 일치함을 확인했다.

서버가 재시작되어 GPU UUID는 같지만 장치 순번이 달라졌고 /mnt/nfs_L 마운트가 사라졌다. 사용자에게 복구 및 실제 경로 확인을 요청했다. 현재 실행 환경에는 dataset/split.json이 없으므로 과거 split을 복사하거나 추측하지 않는다. 데이터 대기 audit와 GPU 자원 확인 scheduler를 실제 PID·PGID·시작 tick·명령과 함께 새 실험 managed_jobs.json에 등록했다. 마감 watchdog도 무장 상태를 확인했다.

공유 NFS의 파일 잠금이 rpc_wait_bit_killable 상태로 검사 프로세스를 멈추는 구체적 실패를 확인했다. 새 실험의 immutable reader 및 세션별 단독 writer HDF5에서만 locking=False를 사용하고 완료 파일을 원자적으로 교체한다. 정지한 합성 fixture만 소유 PID를 검증해 종료했고 수정 후 데이터 검사는 통과했다. 데이터가 아직 없는 audit 대기 프로세스에 동일 수정을 적용해 교체·등록했다. 다른 agent의 GPU 작업은 조작하지 않았다.

학습 준비와 최종 Test는 아직 미실행이다. 실제 split 검증→공통 캐시→동일 3시간 주 trial 6개→전체 Test→원시 재계산 및 첫 6행 보고서→추가 seed 6개 순으로 자동 실행하도록 구현했다. 최종 동일 GPU 속도 및 추가 trial 분석·보고서 감사는 남아 있다.

## 추가 검증

실제 Multi-HMR의 batch16 AMP forward/backward 그래프를 여섯 조건 모두 GPU에서 검사했다. 유한 loss·gradient를 확인했고 이벤트 주센서의 adapter에도 gradient가 전달됨을 확인했다. 이벤트 입력 adapter를 위해 고정된 초기 backbone 블록에도 활성화 checkpoint를 적용했다. 최대 할당 메모리는 약23.45GB였으며 optimizer update나 실제 데이터 미세조정 결과가 아니다.

현재 data_cpu_checks.json, model_gpu_preflight.json, training_graph_gpu_preflight.json과 독립 원시 지표 합성 검사는 통과했다. 캐시/온라인 전체 처리 속도, 동일 GPU 검사, 추가 seed 후속 결과 및 checkpoint/보고서 감사 구현과 대기 프로세스를 연결했다. 실제 dataset/split.json은 여전히 접근 불가하므로 실제 body split·학습·Test 완료로 표시하지 않는다.

## 데이터 접근 차단 감사

동일한 데이터 NFS 마운트 부재를 연속 세 Goal 턴에서 다시 확인했다. 현재 실제 split 동결·실제 학습·Test가 모두 미실행이다. 코드와 합성 CPU/GPU 검사 후 다음 과학적 실행은 실제 데이터 접근 없이는 진행할 수 없다. 사용자에게 요청한 마운트 복구 또는 실제 경로 응답이 필요하다. 데이터 복구 대기 및 사용자 고정 마감 감시 프로세스는 소유 PID·PGID·시작 tick·명령이 일치함을 확인했고 유지한다. 목표 달성을 주장하지 않으며 차단 상태로 기록한다.

## 준비 병목 단축 및 실제 Train 검사

사용자가 GPU 실행을 재요청했다. CPU 영상 디코딩/이벤트 로딩이 선행 준비를 지연시키는 것을 확인했다. 아직 본학습이 시작되지 않은 소유 cache 작업만 신원을 대조해 종료하고, 완료한 12개 세션 캐시는 보존했다. 같은 split·프레임·timestamp·인코딩을 검증한 완료 캐시 재개 검사를 통과했다. CPU worker를 4개에서12개로 늘리고 디코더는 worker당2 thread로 제한했다. 실제 GT를 GPU에서 먼저 복원하며 CPU 캐시를 병행하도록 변경했고, 시작 시각은 최초 준비 작업부터 유지해 전체 비용을 숨기지 않았다.

GPU4에서 실제 Train3세션의 고정48프레임으로 여섯 조건의 짧은 AMP/좌표/gradient 검사를 시작했다. Test를 사용하지 않으며 검사 가중치는 모두 폐기한다. GPU 사용률100%, 유한 gradient 및 실제 optimizer update 성공을 확인했다. 이는 주실험3시간 미세조정 및 Test 성능값이 아니다. 주실험은 전체 고정 공통 학습 캐시가 검증되면 원본 가중치에서 독립 시작한다.

실제 Train gradient 검사가 여섯 조건 모두 완료됐고 각8회 optimizer update가 성공했다. 모든 loss/gradient가 유한했고 검사 가중치는 보존/재사용하지 않았다. Test 및 주실험 성능 지표는 아직 계산하지 않았다.

## 보고서 보조 수치 대조 확대

주표 다섯 지표에 더해 전체GT 검출률·자체 검출 표본·학습 경과/성공 update/고유 프레임·효과크기/상대효과/95%CI/Holm p·동일GPU 처리속도/메모리/parameter를 실제 JSON 원본과 대조하는 검증을 추가했다. 잘못된 CI부호, p값, 프레임 수, 학습 예산을 합성 Markdown에서 변조하면 검사가 거부됨을 확인했다. 합성 검사 통과는 실제 Test 또는 실보고서 완료를 의미하지 않는다. Holm p는 소수다섯자리로 표시해 작은 유한 p값을0으로 오인하지 않게 했다. 자체 검출 표본은 공통표본의 공정 비교 주표와 별도 설명한다.

## 본학습 시작 확인

Test 예측을 보지 않은 단계에서 센서간 대응 공정성을 보완했다. 검출 매칭은 관측 주센서의 원래 픽셀 평면에서 같은 GT 인물을 대상으로 하고, 대응한3차원 예측을 공통 device3 RGB 좌표로 변환해 다섯 지표를 계산한다. 다른 카메라의3D 깊이오차가 기준카메라 재투영에서 검출누락으로 중복 집계될 수 있는 분석적 반례를 확인했다. 비항등 카메라에서 native검출이 정확해도 공통카메라 재투영은 탈락하는 합성검사를 통과했고, 절대root오차5656.85mm 자체는 그대로 유지됨을 확인했다. 매칭에는 추론 후 GT만 사용하고 모델 입력에 GT를 추가하지 않는다. 진행 중 학습은 원래부터 native센서 holdout 매칭을 쓰므로 변경·재시작하지 않았다. 새 Test 매칭 규칙은 모든6조건 및추가seed에 공통 동결했다.
